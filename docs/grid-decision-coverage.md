# Grid controller decision coverage

T1, grid slice. Scope: `01 Battery + Grid Controller.js` and `lib/grid/`. An actuator write below means a Node-RED output to the DVCC, ESS or VE.Bus writer, not a physical write on the GX. A decision can also update context, publish status or emit a bookkeeping, dashboard or alarm message without writing an actuator. The runner's grid scenarios are complementary; this inventory maps unit tests.

Test file names in the tables omit the common `tests/` prefix and `.test.js` suffix. **Existing** means covered before T1; **Added** means covered by T1.

## Input admission, loop state and bookkeeping handoff

| Input or condition | Expected output or state | Unit coverage |
|---|---|---|
| Named Victron input or voltage topic with the configured suffix, including a renamed device | Normalize to the corresponding control topic and store the reading. | Existing: `grid-control`, Victron topology and emitted topics |
| Valid numeric string or number | Store a number and timestamp; consumed Ah becomes a positive deficit; AC load and PV are floored at zero; CT and DC keep their signs. | Existing: `grid-control`, emitted topics and cadence. Added: `grid-input-coverage`, sensor admission and accounting |
| Blank, nonnumeric or nonfinite payload, or a payload that is neither number nor string | Discard it; neither the last reading nor its arrival timestamp changes. | Existing: `grid-control`, null during cadence. Added: `grid-input-coverage`, invalid payloads |
| Unrelated topic | Do not run the loop or update its context. | Added: `grid-input-coverage`, topic admission |
| Ordinary sensor arrival, first CT sample or CT change at most 1 kW since last decision | Store only, without an actuator or bookkeeping output. | Existing: `grid-control`, cadence |
| CT changes by more than 1 kW since last decision, or periodic tick arrives | Decide immediately for the CT step in either direction; decide on scheduled ticks independently of sensor arrival. The next immediate CT decision is measured from the updated baseline. | Existing: `grid-control`, cadence and emitted topics. Added: `grid-input-coverage`, falling step and absent CT baseline |
| Manual command accepted, rejected or cleared | Accepted enable records source and start time; disable clears start time; rejected command preserves the current state. | Added: `grid-input-coverage`, manual enable/disable |
| Manual stop voltage in the inclusive 50–60 V range or outside it | Persist valid bounds (including numeric strings); preserve the prior setting otherwise. | Added: `grid-input-coverage`, manual stop voltage |
| Voltage absent, or consumed Ah absent with manual discharge off | Grey waiting status, no actuator writes, no decision in accounting; still track the hour. Manual discharge only bypasses the consumed-Ah gate. | Existing: `grid-control`, actuator/waiting cases. Added: `grid-input-coverage`, manual enable/disable |
| Valid decision | Keep the latest CT decision baseline if there was a CT reading; persist window, setpoint and limiter/guard state for the next tick; publish green status. | Existing: `grid-control`, cadence and status; `grid-replay`, consecutive control decisions |
| VE.Bus limit changed, hour changed, or both unchanged | Emit on change or rollover (including the second Oslo 02:00), not on the next unchanged tick. If no control hour is stored, recover the old hour from the legacy budget. | Existing: `grid-control`, actuator/waiting and Oslo rollover cases. Added: `grid-input-coverage`, legacy hour fallback |
| Accounting samples or legacy budget present/absent | Pass the previous sample to bookkeeping; use current readings only when reconstructing a legacy sample, otherwise start at zero. Count nonnegative import and PV production; signed DC is informational. | Added: `grid-input-coverage`, sample lag and legacy reconstruction |
| Legacy bookkeeping not acknowledged, failed first handoff, or acknowledged | Pass defined legacy keys only; retry after failure; stop once acknowledged. | Existing: `grid-control`, initial migration and retry. Added: `grid-input-coverage`, omission of missing keys |
| Returned loop outputs | Actuators remain on slots 1–3, alarm on 4, legacy slots 5–7 silent, bookkeeping on 8, logs on 9, dashboard on 10. | Existing: `grid-control`, topology, waiting and actuator cases; `grid-feedback`; `grid-dashboard` |
| Repeated cached sensor values after a source stops updating | Arrival cadence is not proof of freshness. The controller does not yet inhibit stale CT, battery or PV decisions. This is the existing blocked G2-SAFE work, not a new policy. | Existing expected failures in Test GX; see [G2 freshness design](grid-g2-design.md) |

## Loop health helper

`lib/grid/health.js` is consumed by node `64`, not by node `01`. The helper decisions are included here; node `64` wiring and timers beyond the helper are outside this slice.

| Input or condition | Expected output or state | Unit coverage |
|---|---|---|
| Pulse age below or at/above 10 s; first/repeated silence; recovery followed by another silence | Report silence at 10 s. Notify once per incident, recover on a new pulse, and honor the 15-minute alert cooldown across incidents. | Existing: `grid-health`, heartbeat |

## Pure control targets

These are return values of `decideGrid`, not physical writes. `test-gx-charging` below refers to the in-process charging fixture tests.

| Input or condition | Expected output or state | Unit coverage |
|---|---|---|
| Season profile and local hour | Select day ESS/VE.Bus targets except from 22:00 to before 06:00, when night targets apply. | Existing: `controller`, `grid-replay`, `test-gx-charging` |
| No overriding mode | NIGHT takes precedence at 22:00; MORNING is 06:00–12:00, EVENING 17:00–22:00, otherwise OUTSIDE. Evening/outside do not schedule charging. | Existing: `controller`, `grid-control`, `test-gx-charging`. Added: `grid-pure-coverage`, window edges |
| Night deficit above both deadband and morning capacity; morning deficit above deadband | Enable maximum scheduled current; otherwise zero. Capacity uses the full morning window at night and remaining hours in the morning. | Existing: `controller`, `test-gx-charging`. Added: `grid-pure-coverage`, threshold equality |
| Positive usable solar forecast, or absent/stale/future/wrong-day/zero forecast | Convert usable forecast to Ah at configured efficiency, subtract it without going negative, and show `SOL` only for usable forecast. In the morning hold charging strictly above 53.7 V. | Existing: `test-gx-charging`. Added: `grid-pure-coverage`, deficit thresholds and voltage fallback |
| Nonfinite consumed Ah or nonpositive battery voltage | Use zero deficit or nominal reference voltage respectively. Positive reference voltage is floored at 1 V. | Added: `grid-pure-coverage`, nominal reference and missing deficit. The positive sub-1 V clamp is not separately asserted. |
| Manual discharge active and battery at/below stop voltage | Clear manual state and timestamp with the low-voltage reason; use the next eligible window immediately. | Existing: `controller`, `test-gx-charging`. Added: `grid-pure-coverage`, exact stop voltage |
| Manual discharge active; AC load at/below ceiling or above it | When allowed, override force/restoration; ESS is load minus available discharge power with a minimum import floor, and scheduled DVCC is zero. When held, retain the request and expose `MD-HOLD`. | Existing: `controller`, `test-gx-charging`. Added: `grid-pure-coverage`, AC ceiling and hold flag |
| Force off, zero requested watts, or limiter bypassed | Clear the limiter latch; positive bypassed request is immediately allowed. Off/zero do not schedule force charging. | Existing: `test-gx-charging`. Added: `grid-pure-coverage`, latch clearing and flags |
| Force limiter enabled | Start at/below start; retain below release and stop at/above release. Interpolate from request at start to voltage × max current at/below full; show `FC` or `FC-ARMED`. | Existing: `grid-replay`, `test-gx-charging`. Added: `grid-pure-coverage`, armed/bypassed flags |
| Force charging with limited ESS headroom | Request no more than schedule or load plus charge watts. Base DVCC rounds charge watts/reference voltage without a scheduled-current ceiling; final DVCC scales to delivered watts above load, down to zero. | Existing: `grid-replay`, `test-gx-charging`. Added: `grid-pure-coverage`, force/HV interaction |
| HV disabled, above start, inside band, or at/below release | Clear, engage, retain or release latch respectively. Taper ESS toward CT import (zero if CT missing) or AC load during force. Limit changes from finite prior ESS to the configured step; never exceed request. | Existing: `controller`, `grid-replay`, `test-gx-charging`. Added: `grid-pure-coverage`, stale latch and taper floors |
| Fixed HV support eligibility | Requires positive support, HV enabled and latched, CT present, no force/manual and no low-sun veto. Cap at load minus support, with minimum import floor. | Existing: `grid-replay`, `test-gx-charging`. Added: `grid-pure-coverage`, missing CT, floor and exclusions |
| Low-sun veto with positive configured support | Below threshold veto fixed and adaptive support and show `GS-SUN`; equality does not veto. | Added: `grid-pure-coverage`, low sun and hybrid |
| Adaptive/hybrid planning inside support window | Use remaining capacity above reserve (zero available if unknown), remaining current-day adjusted forecast and configured confidence/weak-forecast rules. Spread energy over hours left, add PV assistance, and cap by watts and discharge amps. Outside the window or in HV-only mode, no adaptive planning. | Existing: `controller`, `test-gx-charging`. Added: `grid-pure-coverage`, reserve, forecast, caps and window end |
| Applying adaptive support | Requires positive support and CT; blocked by night, boost, force, manual or low sun. Only hybrid retains adaptive support alongside latched HV. Cap at load minus support with configured/global minimum import; show `GS-A`. | Existing: `test-gx-charging`. Added: `grid-pure-coverage`, exclusions, floor and hybrid |
| Non-night AC load strictly above threshold, without force/manual | Subtract high-load reduction, floor ESS at zero, and show `AC-HIGH`; otherwise no reduction. | Existing: `controller`, `test-gx-charging`. Added: `grid-pure-coverage`, equality and exclusions |
| Guard disabled/no CT, or inactive guard on signed CT | Clear when unavailable; arm only on export with initial compensation capped at 2000 W. | Existing: `controller`, `grid-replay`, `test-gx-charging`. Added: `grid-pure-coverage`, clearing, saturation and zero CT |
| Active guard and 15 s adjustment interval | Before deadline hold; at/after deadline move by half the CT error up to ±200 W, except within the inclusive target-to-target+50 W band. Clamp boost to 0–2000 W and clear at zero. | Existing: `grid-replay`, `test-gx-charging`. Added: `grid-pure-coverage`, timing and deadband edges, signed steps and saturation. Malformed persisted guard data is not separately asserted. |
| Final ESS and DVCC | Take minimum of raw ESS and applicable caps, then apply export import floor. Scale scheduled DVCC to delivered power. Guard DVCC uses PV plus boost, capped at max; choose the greater DVCC, not their sum. | Existing: `controller`, `grid-replay`, `test-gx-charging`. Added: `grid-pure-coverage`, export override of zero ESS and cap. Derived charge watts are not directly asserted. |
| Decision status | Emit applicable mode/limit flags; suppress HV when final ESS exceeds the taper target. `GS` and `FC` can be misleading in the cases below. | Existing: `grid-replay`. Added: `grid-pure-coverage`, flag precedence and interactions |

## Settings, time and accounting helpers

`constants.js` contains data/specs; their bounds are exercised where decisions consume them. Arithmetic and date formatting helpers are covered through the results they produce.

| Input or condition | Expected output or state | Unit coverage |
|---|---|---|
| Missing, inherited or invalid constants override; number, integer or calendar override | Reject invalid values, round discrete settings and validate MMDD (including Feb 29), clamp numeric overrides. | Existing: `controller`, `nodes`. Added: `grid-pure-coverage`, own values, rounding and bounds |
| Missing, invalid or unordered required protection settings | Return no sanitized settings; controller uses defaults. Require HV full > start ≥ release and force-limiter release > start > full within their ranges, including when disabled. | Existing: `controller`, `nodes`. Added: `grid-pure-coverage`, missing and unordered settings. Not every range endpoint is separately asserted. |
| Optional tuning and support mode | Use defaults for missing/invalid tuning; coerce booleans, clamp or round bounded options, reject invalid strict targets, normalize adaptive/hybrid case and fall back to HV-only. | Existing: `controller`, `nodes`. Added: `grid-pure-coverage`, defaults, strict bounds and modes |
| Missing/invalid, zero or signed stored reading | Distinguish missing from measured zero and preserve signed values. `normalizeConsumedAh` has no production call site; sensor admission normalizes the sign separately. | Added: `grid-pure-coverage`, stored readings; `grid-input-coverage`, sensor admission. Existing: `test-gx-charging`, consumed Ah |
| Manual primitive, exact object/boolean aliases or unsupported command | Enable/disable valid commands, preserving source/reason/defaults; reject unsupported values. When aliases conflict, enable currently wins. | Existing: `controller`, `test-gx-charging`. Added: `grid-input-coverage`, `grid-pure-coverage`, command aliases and reason precedence. Conflict ordering is not separately asserted. |
| Ordinary/wrapping/equal-endpoint window | Half-open intervals; equal endpoints mean 24 h. Outside gives zero; inside uses elapsed time to local end, while night planning uses the whole morning. | Existing: `controller`, `grid-dst`. Added: `grid-pure-coverage`, wrapped, all-day and fractional duration. Remaining window across a DST transition is not separately asserted. |
| Forecast absent, invalid timestamp, expired, future or wrong day | Require same-day nonfuture timestamp within age limit; normalize usable metadata and default missing fields. | Existing: `test-gx-charging`. Added: `grid-pure-coverage`, inclusive age and metadata |
| Adjusted forecast slots absent/wrong day, expired, invalid, nonpositive or beyond window | Reject unusable slots; prorate current slot and count whole eligible future slots only for today, even when the window wraps. | Added: `grid-pure-coverage`, fractional slot and filters |
| Wrapping or nonwrapping season; auto, forced or equal dates | Select forced season or apply calendar boundaries; predict the next automatic date and roll year when needed. Equal dates suppress next switch. | Existing: `controller`. Added: `grid-pure-coverage`, nonwrapping boundaries, forced modes, rollover and equal dates |
| Tier and profile configuration | Day ESS is tier minus margin with minimum; round night bonus to 10 W, apply night billing, flag over-tier. Round VE.Bus backstop to half amps with configured headroom and cap. Monthly tier is first inclusive threshold or tier 7 above 25 kW. | Existing: `controller`, `grid-replay`, `test-gx-charging`. Added: `grid-pure-coverage`, cap, tier boundaries and overflow. Separate VE.Bus 1 A floor is unreachable with validated profiles. |
| Ordinary hour, DST gap or repeated hour | Use distinct keys for the repeated hour via offset suffix; reconstruct hour start from elapsed time without ambiguous local date conversion. | Existing: `grid-dst`, `grid-control`. Negative and fractional offsets are not separately asserted. |
| Budget missing, key changed, timestamp corrupt/backward or elapsed forward | Start/reset budget and coverage state where appropriate; repair invalid timestamp, ignore backward integration, integrate nonnegative power over elapsed time. | Existing: `controller`, `grid-dst`, `grid-replay`. Added: `grid-input-coverage`, `grid-pure-coverage`, previous sample, timestamp repair and integration |
| Monthly history line malformed, foreign, legacy or CSV; duplicate or folded hour | Ignore invalid/other month; clamp negative energy, prefer explicit billable energy over inferred billing, keep latest duplicate and both folded hours. | Existing: `controller`, `grid-dst`, `grid-replay`. Added: `grid-pure-coverage`, duplicates and invalid/negative data |

## Actuator output, read-back and dashboard

| Library | Input or condition → expected output or state | Unit coverage |
|---|---|---|
| `readback` | Missing or non-TCP bus address → system bus; TCP → anonymous client. DVCC/ESS → read their respective settings paths; zero is a valid result. | Added: `grid-output-coverage`, settings read-back |
| `readback` | VE.Bus → enumerate matching service names, ignore rejected or wrong instances, and read the current limit from exactly one instance 276. No match or multiple matches → reject. | Added: `grid-output-coverage`, VE.Bus service selection |
| `readback` | Bus method error, invalid `GetValue` variant, connection error/end or 3 s timeout → reject; success or failure → cancel the timeout and close the connection. | Added: `grid-output-coverage`, bus callback errors and in-flight reads |
| `feedback` | Initial or changed finite target (including zero) → write if the gap permits. Unavailable target → no new write, but continue pending verification or due failure probes. | Existing: `grid-feedback`, newer decision. Added: `grid-output-coverage`, unavailable targets |
| `feedback` | Before 4 s verification deadline → hold; at deadline → read. In-flight read blocks another write. Match within tolerance → verify and clear the fault. | Existing: `grid-feedback`, matching and ignored writes. Added: `grid-output-coverage`, verified refresh and recovery |
| `feedback` | First mismatch/error → paced retry. A newer target can replace a retry or a due failure probe and gets its own retry. Same-target retry/reassertion retains the retry marker. | Existing: `grid-feedback`, target changes and hourly reassertion. Added: `grid-output-coverage`, fresh retry budget and read error |
| `feedback` | Retried/probe mismatch or error → failed, retain the evidence and schedule a probe in 10 s. Follow-up probe either recovers or stays failed. VE.Bus can reassert in a new hour but not in the same one. | Existing: `grid-feedback`, ignored writes and hourly reassertion. Added: `grid-output-coverage`, probe deadline, combined alarm and VE.Bus reassertion |
| `feedback` | Verified target changes or periodic refresh → write subject to channel gap; unchanged target without refresh → hold. No faults → reset the incident but retain previous alert time. New incident alerts once subject to a 15 min cooldown. | Existing: `grid-feedback`, match, pacing and alarm. Added: `grid-output-coverage`, per-channel pacing |
| `output-stage` | No decision → null commands. Valid decision → route DVCC/ESS/VE.Bus outputs and record hour on writes. DVCC/ESS are paced at 10.1 s on the monotonic clock and refresh; VE.Bus follows change/hour rules. DVCC/VE.Bus allow read-back tolerance; ESS requires an exact match. | Existing: `grid-control`, `grid-feedback`. Added: `grid-output-coverage`, waiting, channel refresh and alarm |
| `output-stage` | Async read success/error → retain only for the same send still in reading phase; consume once. Errors use their message or string fallback. | Existing: `grid-feedback`, in-flight read. Added: `grid-output-coverage`, stale callbacks and recovery |
| `output-stage` | Faults → red status. Eligible notice → GX alarm, dated log entry and counter increment; suppressed notice → none of these. Recovery clears the active alarm. Scheduled tick, not an immediate CT decision, publishes the monotonic heartbeat. | Added: `grid-output-coverage`, combined alarm, recovery and monotonic heartbeat |
| `dashboard` | No prior channel data → not sent. Finite read/error → matching, mismatching or failed read status; no fresh read or retry of same target → retain read history. Changed target clears the old read. | Existing: `grid-dashboard`, retry and new target. Added: `grid-output-coverage`, waiting and matching probes |
| `dashboard` | Waiting reason overrides flags; otherwise show flags or schedule. Targets appear only with a decision. Missing arrivals are null; missing loop health uses zero/null defaults. Publish current counter and wall timestamp. | Added: `grid-output-coverage`, waiting, reason precedence and combined alarm |
| `dashboard` | Publish an initial or changed snapshot at least 2 s apart on the monotonic clock. Suppress unchanged or too-early snapshots. Wall time is reported but excluded from change detection. | Existing: `grid-dashboard`, changes and pacing. Added: `grid-output-coverage`, unchanged fault and waiting timestamp |

### Confirmed gaps (not fixed in T1)

| Decision or contract | Current behavior | Follow-up |
|---|---|---|
| Keep at least 15 real minutes between separate alarm notices | Feedback compares wall timestamps. A 20-minute forward clock jump after recovery let the next incident notify only 4 elapsed seconds after the first. | `G3-COOLDOWN` |
| Count feedback notices for the current Oslo day | The context counter accumulates across midnight although events are written to separate daily files. The current UI does not label the count daily. | `G3-DAILY` |
| Distinguish accepted commands from sustained failure to track the physical target | Read-back verifies the three command paths; it does not detect sustained divergence between physical import and the requested ESS target, as described in the G3 plan. | `G3-TRACKING` |
| Preview an accepted Feb 29 season boundary | From November 2027, a Feb 29 winter start displays March 1, 2028; the actual switch is February 29, 2028. The next-date calculation normalizes February 29 in the wrong year before rolling forward. | `T1-GRID-LEAP` |
| Show fixed HV support only when its cap is applied | With no CT, ESS follows the HV taper rather than the fixed support cap, but a `GS:<watts>(HV)` flag can still appear. | `T1-GRID-FLAGS` |
| Show force charging only when its mode wins | Manual discharge can win with zero DVCC and still show an `FC` flag alongside `MD`. Control targets are correct; the status is misleading. | `T1-GRID-FLAGS` |

Each added test was checked against at least one narrowly targeted mutation of loaded source in memory. No mutation or production change is included in this branch.
